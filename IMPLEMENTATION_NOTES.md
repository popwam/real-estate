## Company Verification / Platform Settings / Selectors / Map / Access Levels / i18n

- Verification lifecycle: organizations now support the stricter lifecycle statuses from draft/document review through verified, active, rejected, suspended, and expired. New platform-created companies are not published or activated immediately.
- Required document policy: added platform-configurable required document policies by country, organization type, legal form, document type, owner-document requirement, expiry requirement, and owner roles. A default Egypt/BROKERAGE policy blocks activation until commercial register, tax, address, and owner/signatory documents are approved.
- Activation gate: `POST /platform/organizations/:id/activate` returns a structured checklist when activation is blocked. Activation requires approved required documents, owner document readiness, active/trial subscription, plan, limits, active office, first admin, and no rejected/suspended/expired organization status.
- Manual review UI: platform organization details now show an activation checklist and document review controls. AI/OCR extraction remains separate from approval; extracted data is not auto-approved or auto-applied.
- Platform Settings: added `/platform/settings`, `/platform/settings/plans`, `/platform/settings/subscriptions`, `/platform/settings/verification-policies`, `/platform/settings/modules`, and `/platform/settings/domains` for platform-owned configuration.
- Controlled selectors: organization type, plan, country, currency, language, timezone, legal form, document type, owner role, billing cycle, modules, and permissions use controlled select-style inputs where implemented. API payloads continue to send stable codes such as `BROKERAGE`, `EG`, and `EGP`.
- Company wizard integration: the wizard preserves client state on API errors, uses metadata-backed selectors, uses Platform Settings plans when available, creates companies as draft/verification states, and does not activate them directly.
- MapPicker: added a reusable `MapPicker` and wired it into company wizard office/attendance steps, platform organization office/attendance tabs, and HR branch settings. Coordinates are under Advanced details; browser geolocation is supported; map-provider-missing messaging is localized.
- Multi-office limits: office creation continues to enforce `maxOffices`/`maxBranches` through backend provisioning limits. Deactivated offices are not counted as active offices for the active-office activation check.
- Wi-Fi UX: Wi-Fi forms keep SSID as sufficient, BSSID/MAC optional, and show the browser limitation message. Web Wi-Fi policy remains `BLOCK`, `MANUAL_REVIEW`, or `IGNORE_FOR_WEB`.
- Company access levels: added `CompanyRoleTemplate` and organization-scoped access-level APIs/UI. Company admins cannot assign platform permissions; route and sidebar access still depend on real permissions rather than display names.
- Subscription and first admin lock: non-platform users are blocked from company workspace access until the organization is `ACTIVE` or legacy `APPROVED`; the message explains that the company is awaiting platform verification. Suspended/expired/cancelled subscriptions remain blocked.
- Permissions: added platform settings/plans/subscriptions/verification-policy/document-review/activation permissions and company access-level/office/Wi-Fi/attendance-location permissions, with backend checks and platform/company scoping.
- Language/i18n cleanup: added EN/AR/FR strings for verification, Platform Settings, MapPicker, access levels, activation, and selectors. The visible placeholder `نص مترجم` is not present in runtime source. i18n audit reports missing Arabic/French keys as zero.
- Domain defaults: fallback public links use the configured fallback path, defaulting to `/sites`, and wildcard subdomains remain disabled unless explicitly enabled. DNS/Railway success is not faked.
- Tests: ran Prisma validate/generate, API tests/build, Admin lint/build, Public lint/build, both i18n audits, and `git diff --check`.
- Manual QA: create a BROKERAGE/EG draft company, confirm required documents block activation, upload/review documents through protected APIs, approve required documents manually, confirm activation checklist clears, activate the company, verify first admin access only after activation, add offices up to `maxOffices`, add a Wi-Fi rule with SSID only, create a company access level, and verify Arabic/French UI does not show placeholder text.
